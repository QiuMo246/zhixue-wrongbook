### 教训（可复用）

1. **增量写入时，派生字段不能被来源数据覆盖。** 同步来的原始数据里没有「分析结果」，
   但分析结果是同一张表的列 —— 无条件 UPDATE 就等于删数据。派生字段要用
   `COALESCE` 或「非空才覆盖」。
2. **回归测试要断言不变量在两个方向都成立。** 「不会变多」通过了，不等于「不会变少」也通过。
   幂等性测试必须检查「原有内容是否还在」，而不只是「数量对不对」。
3. **`ok=true` 不等于「你要的东西生成了」。** 同一 server 里参数命名不一致
   （`zx_export_wrongbook(fmt=)` vs `zx_export_paper(want_pdf=)`）+ pydantic 默认丢弃未知字段
   = 传错参数名会静默「成功」。凡是「可选产物」型参数，返回里都该带产物是否真的存在。

### 学生版第一版有个严重疏漏（秋末当场指出）

**只摆了「标准答案 vs 你写的」，却没给题干。** 学生根本不知道第9题问的是什么 ——
错题报告没有题干等于没写。已修：每题现在带**完整题干 + 配图**。

**顺带发现的三个坑**：

1. **库里 id 的序号是 4 位（`0001`），图片文件名是 3 位（`001`）** ——
   直接拼字符串 glob 会一个都匹配不到，而且**不报错**（生成出 77 KB 的"没有图"版本）。
   现在加了"找不到配图就打印警告"，并且用 `f"{n:03d}"` 格式化。
   **教训：静默匹配不到比报错危险。凡 glob 都要断言命中数。**

2. **题干里全是 LaTeX 残渣**（`\frac{s}{2}`、`30^{\circ}`、`\textcircled1`）——
   学生看不懂。写了个清洗器，**顺序很关键**：
   ```
   \textcircled1 和 {^\circ}  必须先处理（它们自带花括号）
   → 再 \mathrm / \text
   → 再 \frac
   → 最后才去孤立花括号
   ```
   顺序错的话 `\frac{100 {^\circ}\mathrm{C} }{20cm}` 会变成 `\frac100 ^°C 20cm`（乱码）。
   验证方法：生成后扫 `\\[a-zA-Z]+`，必须为 0。

3. **`**粗体**` 是 Markdown 语法**，直接塞进 HTML 会显示字面星号 →
   `md()` 助手：先 `html.escape` 再正则替换。

## 追加：诊断闸门升级为「科目 + 试卷范围」两问（12:03–12:30）

**需求（秋末提的）**：在生成个性化报告之前，AI 不仅要问科目，
**还必须问「要分析哪些试卷里的错题」**，按两个维度选：
① 试卷类型（周测/午练/晚练/早读）② 时间（如本周）。两问都拿到才能出报告。

**关键判断：这条规则光写文档没用，必须让「不给范围就拿不到数据」成为确定性事实。**
所以动了五层：

| 层 | 改动 |
|---|---|
| `core/constants.py` | 新增 `PAPER_TYPES`（周测/午练/晚练/早读 + 其他/全部）、`TIME_SCOPES`（本周/上周/近两周/本月/近一月/全部）、两套别名表 |
| **`core/scope.py`（新）** | 归一化、时间区间解析（**周一起算**）、选项清单（带题数）、`resolve_scope`、`ask_user_scope_prompt`（两问一次问完） |
| `core/store.py` | `query()` 加 `paper_types`/`date_from`/`date_to`；新增 `count_questions()` / `counts_by_paper_type()`；`log_diagnosis()` 加 `paper_types`/`time_scope`/`scope_confirmed`；`_migrate()` 扩到 `diagnosis_log` |
| `core/profile.py` | `build_profile()` 接受范围参数并**真的过滤**，输出里回显 `scope` |
| `server.py` | `_subject_gate` → **`_diagnosis_gate`（七道检查）**；`zx_diagnosis`/`zx_profile` 加三个参数 |

**七道检查（顺序有讲究：先问完再查数据，别让用户白答）**：
缺科目 → 科目未确认 → **缺范围** → **范围非法** → **范围未确认** →
该科无数据 → **该范围无数据**。

**「其他」这个类型是必须的**：库里还有「期末测试」「期中模拟」这类卷子，
只列四类的话这部分错题**永远选不到** —— 比不筛还糟。

**最容易写错的一处**：「其他」= 4 个 `NOT LIKE` 的 **AND**。
写成 OR 会永远成立（等于没筛），而且**不报错**，只在数据上表现为
「其他 = 全量」。已专门加了断言兜底。

**另一个刻意的设计**：范围里没题时**不自己放宽成「全部」**，
而是把可选范围重新给用户让他选 —— 放宽就等于又替用户决定了。

**测试**：`edge_test.py` 新增 T 段 36 项（`mcp_e2e.py` 加 5 项）。
刻意测三层：闸门七态 / **范围真的过滤了数据** / 审计日志记下范围。
第二层最关键 —— 只测「有没有拒绝」的话，闸门可能只是句问话。

**回归**：acceptance 66/66 + edge_test 179/179 + mcp_e2e 41/41 = **286/286**
（原 245，新增 41 项）。老库迁移也在测试里覆盖（建一张缺列的表 → 验证自动补列 + 能写）。

**踩坑**：测试里日期写错一次 —— 期末题在 09-20，我把下界写成 09-21，
断言 `== 3` 实际得 2。**写日期断言前先把数据的时间线列一遍**，别凭印象。
