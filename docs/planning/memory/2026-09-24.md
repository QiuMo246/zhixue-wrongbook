### 关键技术发现（重要，下次继续要用）

1. **装的是 `zhixuewang==1.5.1`，不是文档示例里的 2.x.x。**
2. **`login_cookie` 的字符串解析有真实缺陷**（`account.py:56-59`）：
   按 `"; "` 切分、`dict(item.split("="))` 遇值内含 `=` 会 ValueError、
   强制读 `loginUserName` 否则 KeyError。→ 我们在 `adapters/zhixuewang.py`
   的 `parse_cookie_string()` 自己解析成 dict 再传给库。
   **照抄设计文档第 11 节的示例代码有概率直接报错。**
3. **`ErrorBookTopic.difficulty` 类型是 `int`（models.py:469），不是文档假设的 0~1 浮点。**
   → 新增 `config.yaml` 的 `difficulty.scale`（默认 unknown），
   未核实时难度闸门**自动降级为软参考**，不假装有效。
4. **`standard_answer` 源码注释写 `# 网址`（models.py:474）**，可能不是文本。
   → 适配器检测 URL 并回退到 `answer_html`。
5. **`ErrorBookTopic.subject_name` 实际装的是 `paperName`（student.py:846）**，是试卷名不是学科名。
6. **`get_errorbook(exam_id, topic_set_id)` 的第二个参数存疑**：形参叫 topic_set_id，
   请求键名却是 `paperId`；`get_subjects()` 的 Subject.id 来自 paperId，
   `get_latest_exam()` 的来自 topicSetId。→ 失败自动重试另一条。
7. **平台很可能自带考点数据**：`student/urls.py:41` 有
   `GET_LOST_TOPIC_URL = .../getExamPointsAndScoringAbility`（考点与得分能力），
   **但全库零引用（库没封装）**。若它返回结构化知识点，
   文档「知识点标注是本工具核心价值」的前提就不成立。已预置探测代码。
8. **`get_answer_records()` 不返回学生作答文本**（models.py:405-411 的 TopicRecord
   只有 title/score/standard_score），客观题也拿不到作答。
9. **`login_playwright` 用 `browser.new_context()`（account.py:66-67）**，
   不是 persistent context → 文档担心的 profile 占用冲突对该库不成立。
10. **mcp 2.x 把 `FastMCP` 改名成 `MCPServer`**（`mcp.server.mcpserver`）。
    server.py 里做了双版本兼容的导入。

### 查出并修掉的真 bug（第 3、4 个）

3. **`make_id` 漏了考试维度**（`adapters/parsers/normalize.py`）
   `id` 是 `questions` 表的**主键**，但生成规则是 `zx_<年>_<学科>_<序号>`，
   而 `seq` 是「每场考试 × 每学科」内部从 1 重来的。于是同一年两场数学考试的
   第 1 题都算成 `zx_2026_math_0001` —— 第一场 15 题入库成功，
   第二场 **12 题全部**报 `UNIQUE constraint failed: questions.id`。
   → 补上考试摘要（`exam_name + exam_date` 的 sha1 前 4 位），
   形如 `zx_2026_math_3f2a_0001`。函数签名里本来就有 `exam_name` 参数、
   只是函数体没用 —— 原设计就打算这么做。
   → 另在 `core/store.py` 的 `upsert` 加兜底：id 被占用时改用
   `原id-指纹前6位` 重试，记进 `store.id_fallbacks`，
   由 `sync()` 报进 report 的 notes + warnings（不静默）。

4. **测试套件会删掉用户真实凭据**（`tools/mcp_e2e.py` + `tools/edge_test.py`）
   两个测试只把 `ZX_DB_PATH` 指到临时库，就以为「不碰真实数据」了。
   但**凭据存储不属于数据库** —— `mcp_e2e.py` 调的 `zx_session_clear`
   真的把秋末存在 Windows 凭据管理器里的 `zhixue-wrongbook / zx_cookie` **删了**，
   害他被迫重新登录一次。
   → `adapters/session.py` 把凭据命名空间做成环境变量可覆盖：
   `ZX_CRED_SERVICE` / `ZX_CRED_KEY` / `ZX_CRED_FILE`；
   两个测试各自指向一次性命名空间。
   **验证方式**：往真实命名空间写哨兵 → 跑完三套测试 → 哨兵原封不动 → 清理。

### 本轮修的缺陷（都在真实使用路径上暴露）

5. **#9 MCP 工具错误处理不对称**（`server.py`）
   16 个工具里 **11 个没有顶层 `except`** —— 只有为 `store.close()` 写的

## 23:40 新增功能：个性化诊断前必须强制询问科目

**需求（秋末提的）**：在用户让 AI 根据错题生成「个性化诊断」之前，
助手必须**强制询问**用户要诊断哪一科（语文/数学/英语/物理/历史/道法…）。

**关键判断：只写提示词拦不住模型，所以落到数据面做成确定性闸门。**

落地方式（两道闸门 + 一条留痕）：

| 机制 | 位置 | 性质 |
|---|---|---|
| 科目必填，缺失即拒绝 + 返回 `ask_user` 话术 | `zx_diagnosis` / `zx_profile` | 确定性 |
| `user_confirmed` 必须 true，否则拒绝 | 同上 | 声明式，可伪造但留痕 |
| 每次通过的诊断写 `diagnosis_log` | SQLite 新表 | 审计 |
| 「先问科目」写进硬规则 0 | `skill/.../SKILL.md` | 提示词级 |

**闸门三道检查的顺序是有意的**：先「问什么」（缺科目→给候选清单），
再「问没问」（未确认→给问话），最后「这科有没有数据」（无数据→让用户先同步）。
反过来的话用户会被问一科、答完才被告知没数据，白问一轮。

**新增/改动**：
- `core/subjects.py`（新）：科目清单 = `constants.SUBJECT_ORDER` ∪ 词表 ∪ 本地库；
  `ask_user_prompt()` 给宿主一句可直接照读的话术。
- `core/constants.py`：加 `SUBJECT_ORDER`（固定学科顺序）+ `SUBJECT_ALIASES`（政治→道法）。
- `core/store.py`：加 `subject_stats()`、`diagnosis_log` 表、`log_diagnosis()`、`diagnosis_logs()`。
- `server.py`：加 `_subject_gate()` + `zx_subjects` / `zx_diagnosis` / `zx_diagnosis_log`；
  `zx_profile` 的 subject 从「可选默认全部」改必填 + 加确认闸门（不堵这里闸门就有旁路）。
- 测试：acceptance 44→51 项、mcp_e2e 24→32 项（含闸门三态）。三套合计 **195 项全绿**。
- 文档：README 新增一节、架构设计 6.1 节、验收报告 4.12/5.2/5.4/6.1。

**两条刻意的设计决定（都是「不让数据替用户做决定」）**：
1. 科目清单**按固定学科顺序排，不按题数排** —— 按题数排等于题最多的那科永远第一。
2. `live_smoke.py` **刻意不用 `zx_diagnosis`**（改用 `zx_profile`）——
   无人值守脚本没有真实用户确认，走 `zx_diagnosis` 会在真实库里写一条

**诚实边界（写进 README/架构/验收三处）**：
机器只能强制「必须声明已询问」，**不能**验证用户真的被问过 ——
`user_confirmed=true` 终究是宿主的一句声明。所以退一步让声明留痕，
