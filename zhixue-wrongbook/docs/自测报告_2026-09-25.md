## 4. 🔴 P0 缺陷：重新同步会**清空**已提交的分析结果

### 4.1 实测证据（真实账号触发）

跑 `live_smoke.py` 前后对比真实库：

| | 总题数 | 有 `analysis` | `needs_review=true` |
|---|---|---|---|
| 同步前 | 27 | **27** | 27 |
| 同步后 | 27 | **0** | 0 |

**27 道题的分析结果（含知识点、错因、`analyzed_by`、`prompt_version`）全部变成 NULL。**

### 4.2 离线最小复现（不联网、不需要账号）

```
① 初始状态: 总题=27  有analysis=27  有practice=3
  选中题目 id=zx_2026_math_1372_0001  指纹=aeb55744a731c4db…
  当前有分析结果: True  → 错因=方法选择错误
  重新 upsert 同一道题 → 返回 'updated'（指纹去重生效了）
② 重新 upsert 之后: 总题=27  有analysis=26

❌ 复现成功：有分析结果的题从 27 掉到 26
```

脚本：`out/_selftest/repro_wipe.py`

### 4.3 根因

`core/store.py` 的 `upsert()`，题目已存在时执行全字段 UPDATE：

```sql
UPDATE questions SET
    ...,
    analysis=?, practice=?, history=?
WHERE fingerprint=?
```

而 `core/models.py:247` 里：

```python
"analysis": self.analysis.model_dump() if self.analysis else None,
```

**新同步来的题天然没有分析结果**（分析是宿主后来通过 `submit_analysis` 提交的），
于是这个 `None` 直接盖掉了库里的分析结果。`practice` 和 `history` 同理。

### 4.4 为什么这是 P0

1. **静默** —— `zx_sync` 返回 `ok=true`，`updated=27`，**没有任何警告**
2. **违反自己的文档** —— `store.py` 的 docstring 写「只更新会变的部分（得分、分析结果、历史）」，
   设计文档 §7 也把分析当作题目记录的一部分
3. **毁掉的是最贵的东西** —— 分析结果是 AI 花 token、花时间读题 + 读手写图片产出的，
   重新同步只是「又抓了一次接口」，却把它清了
4. **日常操作就会触发** —— 用户每周同步一次新错题，就会把上周的分析全部清掉

### 4.5 为什么 214 项测试没抓到

离线套件里有「指纹去重：同一题入库两次只更新不新增」——
但它**只断言了题数不变**，没有断言「分析结果还在」。
**测了「不会变多」，没测「不会变少」。**

### 4.6 建议修法

在 `upsert()` 的 UPDATE 分支里，**只在传入值非空时才覆盖**这三列：

```python
# 方案 A：SQL 层用 COALESCE / CASE
analysis = COALESCE(?, analysis),
practice = CASE WHEN ? = '[]' THEN practice ELSE ? END,
history  = CASE WHEN ? = '[]' THEN history ELSE ? END,

# 方案 B：Python 层先读旧值，空则沿用
existing = self.conn.execute(
    "SELECT analysis, practice, history FROM questions WHERE fingerprint=?",
    (fp,)).fetchone()
if row["analysis"] is None:
    row["analysis"] = json.loads(existing["analysis"]) if existing["analysis"] else None
```

**并补一条回归测试**：upsert 两次后，断言 `analysis` / `practice` / `history` 仍在。

## 5. 其它缺陷

### 🟠 缺陷 2（中级）：未知参数被**静默忽略**，还返回 `ok=true`

```
zx_export_paper(items=..., want_pdf=True)     → ok=true, 真产出 PDF
zx_export_paper(items=..., fmt="pdf")         → ok=true, 没有 PDF，也没有任何提示
zx_export_paper(items=..., 完全不存在="xxx")   → ok=true, 静默通过
```

`fmt` 不是这个工具的参数（它属于 `zx_export_wrongbook`），
但 pydantic 默认丢弃未知字段 → 调用「成功」了，产物却不存在。

**成因**：同 server 里两个导出工具参数命名不一致 ——
`zx_export_wrongbook` 用 `fmt="md"|"xlsx"`，`zx_export_paper` 用 `want_pdf=True`。
宿主很自然地把前者的习惯套到后者身上。

**修法**：① 统一命名；② 让未知参数报错（`extra="forbid"` 或入口自检）；
③ 「可选产物」型参数在返回里带上产物**是否真的存在**（路径 + 大小）。

### 🟠 缺陷 3（中级）：列表型参数声明为 `str`，传数组在调用层就被拒

| 参数 | 传 `[]` | 传 `"[]"` |
|---|---|---|
| `submit_analysis.knowledge_points` | ❌ ToolError | ✅ |
| `submit_analysis.evidence` | ❌ ToolError | ✅ |
| `zx_sync.subjects` | ❌ ToolError | ✅ |
| `zx_export_paper.items` | ❌ ToolError | ✅ |
| `check_practice.candidate` | ❌ ToolError | ✅ |

被拒时**吐的是一屏 pydantic 报错 + Python 堆栈**，调用方完全看不懂。

而**设计文档 §7 把 `knowledge_points` / `evidence` 画成数组**，
`submit_analysis` 的工具描述里又**完全没写**该传什么形状 —— 宿主照文档写，必踩。

**修法**：签名放宽为 `str | list[str]`（函数体里的 `_split()` 已经能吃两种字符串形状，加个 list 分支即可）。

### 🟠 缺陷 4（中级）：会话失效时泄露 Python 异常

```
{"has_cookie": true, "valid": false,
 "error": "TypeError: 'NoneType' object is not subscriptable",
 "hint": "Cookie 可能已过期，请用 zx_session_set 更新。"}
```

**根因**（完整堆栈已定位）：`zhixuewang/account.py:18` → `return data["result"]["role"]`。
服务器对失效 Cookie 返回 `{"errorCode":-200,"errorInfo":"操作失败","result":null}`，
`data["result"]` 是 `None`，再取 `["role"]` 抛 `TypeError`。

**实测对照**（区分「Cookie 过期」与「网络问题」）：

```
走环境变量代理    → HTTP 200  {"errorCode":-200,"errorInfo":"操作失败","result":null}
不走代理          → HTTP 200  {"errorCode":-200,"errorInfo":"操作失败","result":null}
完全不带 Cookie   → HTTP 200  {"errorCode":-200,"errorInfo":"操作失败","result":null}
```

三者完全一致 → 确认是 **Cookie 失效**，与代理无关。

**修法**：识别 `errorCode != 0 / result is None`，换成
「会话已失效（服务器返回 errorCode=-200），请重新提供 Cookie」。

### 🟡 缺陷 5（低级）：`verify_p0.py` 的建议不读配置，给出**已过时**的指引

`tools/verify_p0.py:252-255`：只要难度值是 `int > 1`，就无条件打印

> 「请把 config.yaml 的 `difficulty.scale` 改成 raw，`assumed_max` 填实际最大值」

但 `config.yaml` **早就已经是** `scale: raw` / `assumed_max: 3`（还带 314 个样本的实测依据）。

**修法**：打印建议前先读 `get_config()`，已符合就改成「✅ 与当前 config 一致」。

### 🟡 缺陷 7（低级）：`ZX_DB_PATH` 传相对路径时静默新建空库

测试时踩出来的：通过 shell 传了 POSIX 风格路径 `/d/Data/...`，
Python 在 Windows 上解析成**当前盘符下的相对路径** `\d\Data\...`，于是：

- 在别处**新建了一个空库**（53 KB，0 行）
- 工具照常运行，只是所有科目都显示「0 道题」
- 用户看到「本地还没有任何错题数据」，**没有任何提示说"你可能指错了库"**

**修法**：`Config.path()` 里对非绝对路径报错或按 ROOT 解析；
并考虑「库文件不存在时提示」而不是静默建空库。
