# 智学网错题助手 · 架构设计方案

> 目标：在 AI 编程助手中通过 Skill + MCP 集成，连接智学网学生端账号，自动获取错题并完成
> **整理错题集 → 逐题错因分析 → 知识点归纳 → 同类题针对性练习** 的闭环。

---

## 0. 前提事实（已核实，决定全部架构走向）

| # | 事实 | 架构影响 |
|---|---|---|
| 1 | 智学网**无面向学生/第三方的开放 API**；仅有社区逆向库 `anwenhu/zhixuewang-python`，能力为考试列表、科目成绩/总分、作业状态、批改进度、**原卷下载**，**无错题逐题结构化接口** | 错题不是"取到的"，是"拼出来的"（见 §3.3） |
| 2 | 登录需**浏览器自动化 + 人工过验证码**，或**注入已有会话 Cookie** | 全自动登录不可行；凭据必须绕开模型 |
| 3 | 该库明确记录"近期平台改版影响学生端 Web 能力" | **脆弱性是一等公民约束**，需快照重放与失效告警 |

**核心主轴**：把外部不确定性与依赖全部关进一个**可替换的采集层**，让上层分析与生题逻辑只依赖一份本地规范化数据模型。

---

## 1. 形态选型：Skill / MCP / 混合

| 方案 | 做法 | 问题 |
|---|---|---|
| A. 纯 Skill | 提示词驱动现成 browser MCP 点页面 | 会话/凭据暴露在 Agent 上下文；解析逻辑不可测；无稳定存储 |
| B. 纯 MCP | 全部能力封成 tools | 错因归纳、出题本质是 LLM 推理，塞进工具内变成"工具里偷偷调模型"，不可审计 |
| **C. 混合 ✅** | **MCP 管有状态/需凭据/需确定性验证；Skill 管编排与推理提示** | — |

**分工界线（本方案的设计要点）**

- **进 MCP**：登录与会话、采集、解析归一化、存储、去重聚类、**出题校验器**、导出。
  理由：凭据绝不能进入模型上下文；校验必须是确定性代码，而非模型自述。
- **进 Skill**：错因归类提示、知识点标注的解释性输出、诊断报告成文、
  "同步 → 诊断 → 组卷 → 复盘"的编排顺序与话术。

## 2. 分层架构

```
┌─ L0 会话与授权  AuthBridge ──────────────────────────────┐
│  交互式登录 / Cookie 保险库 / 有效性探针 / 范围与限速     │
└───────────────────────┬──────────────────────────────────┘
┌─ L1 采集  Collector（可插拔多后端）──────────────────────┐
│  BrowserCollector(主) │ ExportCollector(兜底) │ ApiCollector(可选)│
│      ↓ 不可变原始快照 raw_artifact + 游标增量             │
└───────────────────────┬──────────────────────────────────┘
┌─ L2 解析归一化  Normalizer ──────────────────────────────┐
│  逐题得分表 ⋈ 原卷内容/OCR → WrongQuestion → 校验 → 落库  │
└───────────────────────┬──────────────────────────────────┘
                        ↓   SQLite(FTS5) + 图片资产目录
┌─ L3 认知分析（LLM，受证据约束）──────────────────────────┐
│  ErrorAnalyst 错因 │ KnowledgeTagger 知识点(锚定 KP 树)   │
│  CollectionBuilder 去重/聚类/掌握度                       │
└───────────────────────┬──────────────────────────────────┘
┌─ L4 练习生成  Generator + Verifier 门禁 ─────────────────┐
│  G1检索同型题 / G2参数化变式 / G3 LLM仿写 → 五道校验 → 组卷│
└───────────────────────┬──────────────────────────────────┘
                        ↓
┌─ L5 对外：MCP tool surface + Skill 编排 + 导出 ──────────┐
   练习闭环作答 → attempt 回写 → 掌握度更新（回到 L3）
```

## 3. 模块详设

### 3.1 AuthBridge（授权与会话）

- **两种绑定方式，均不经手明文密码**
  1. 交互登录：MCP 拉起浏览器，用户自行输入账号密码 + 过验证码；程序只等待"登录成功"事件，然后收割会话 Cookie。
  2. 会话导入：用户从已登录浏览器导出并粘贴 Cookie。
- **存储**：OS keychain（Windows Credential Manager）加密落盘；密钥不进仓库、不进日志。
- **有效性探针 `zx_status` 状态机**：
  `未绑定 / 会话有效 / 需重新登录 / 风控拦截 / 平台改版解析失效`
  — 最后一种**必须由解析层失败率自动触发**，不能等用户报"抓不到"。
- **强制约束**：只读端点白名单、请求节流、单次会话请求上限、一键注销。

### 3.2 Collector（采集，可替换后端）

统一接口 `collect(scope, cursor) -> [RawArtifact]`，三实现按能力协商降级：

| 后端 | 手段 | 强项 | 短板 | 定位 |
|---|---|---|---|---|
| **ExportCollector** | 用户上传错题本截图 / 打印 PDF / 原卷图片 → VLM 解析 | 零协议风险、最合规、几乎不脆弱 | 人工步骤多、批量差 | **MVP 首选 + 永久兜底** |
| **BrowserCollector** | Playwright/CDP：DOM + **网络响应拦截** | 页面可见即可得；对协议变化不敏感 | 慢、需 GUI、DOM 会变 | **主路径** |
| **ApiCollector** | 直连私有接口（参考 `zhixuewang-python`） | 快、结构好、可批量 | 需逆向签名、无错题接口、ToS 风险最高 | **默认关闭的加速插件** |

设计要点：

- **能力协商**优先于硬编码顺序：错题类只有浏览器可得 → Browser；成绩元数据 API 更快 → API。
- **原始快照不可变留存**：解析器升级后可**离线重放**，无需重新抓取或重新登录 —— 对抗"平台改版"最有价值的一条设计。
- **增量游标**：`examId / updatedAt / 内容哈希`，避免每次全量。

### 3.3 Normalizer（解析与归一化）— 本方案地基

**关键判断：智学网的"错题"不是可直接取到的对象，而是两个数据源的拼接结果。**

```
逐题得分表 (题号, 得分, 满分, 是否选做)   ← 成绩明细 / 批改详情
        ⋈  join on (exam_id, question_no)
试卷内容   (题号 → 题干 / 选项 / 答案 / 解析) ← 原卷图片/PDF，需 OCR 或 VLM 抽取
```

规范模型 `WrongQuestion`：

```jsonc
{
  "id": "wq_01H...",
  "exam": { "id": "...", "name": "九年级第一次月考", "date": "2026-09-12" },
  "subject": "math",
  "question_no": "18",
  "qtype": "解答题",                 // 单选/多选/填空/解答/作文...
  "stem":   { "text": "...", "image_refs": ["img://..."], "ocr_conf": 0.93 },
  "options": [ { "key": "A", "text": "..." } ],
  "student_answer":    { "text": "...", "image_ref": "img://作答图" },
  "standard_answer":   { "text": "...", "source": "official|derived|unknown" },
  "score":             { "got": 3, "max": 10, "breakdown": [ /* 步骤分 */ ] },
  "official_analysis": null,          // 有则优先，不用模型覆盖它
  "error_tags":        [ /* L3 写入 */ ],
  "knowledge_points":  [ { "kp_id": "K-1.3.2", "conf": 0.88, "why": "..." } ],
  "provenance":        [ { "artifact": "raw_42", "page": 3, "bbox": [0,0,0,0] } ], // 证据链
  "parse_confidence":  0.81
}
```

**必须显式建模的降级态**：`standard_answer.source = "unknown"`（原卷只有题没有答案，或答案仅教师端可见）。
此时错因分析只能输出"可能错因"并标低置信度，**绝不允许模型编造标准答案再据此归因** —— 这是此类系统最常见的致命错误。

### 3.4 Store（本地存储）

- SQLite + FTS5 全文检索；图片走文件资产目录，DB 存 `img://` 引用。
- 表：`exam / raw_artifact / wrong_question / image / knowledge_point / question_kp / error_tag / cluster / practice_item / attempt / mastery_state`
- **默认纯本地，不上云、不遥测。** 学生个人信息 + 未成年人数据，这条不做成开关，做成缺省。

### 3.5 ErrorAnalyst（逐题错因分析）

- **固定错因分类学**（禁止自由发挥，否则无法聚合统计）：
  `知识缺失 / 概念混淆 / 审题遗漏 / 条件误读 / 计算失误 / 方法选择错误 / 表达规范失分 / 时间策略 / 猜测作答 / 未判定`
- **证据约束输出**：每个标签必须引用学生作答与标准答案中的原文 span；无 span 则拒绝该标签。
- **首次分歧定位**：对"我的解答 → 正确解答"做步骤对齐，指出**第一个偏离的步骤**，而非笼统"不会做"。`score.breakdown` 步骤分在此价值极大。
- `未判定` 是一等公民：凑数标签会污染整张诊断矩阵。

### 3.6 KnowledgeTagger（知识点归纳）

- **锚定权威知识点树**：内置可版本化的课标/教材版本 KP 包（JSON）。
  **不用 LLM 自由生成标签** —— 自由标签无法跨题聚合、无法生成热力图、无法做父子一致性校验。
- 两段式：embedding 召回候选 KP（约 20 个）→ LLM 在候选集内多选并给理由 + 置信度。
- 约束：叶节点优先；父子包含/互斥校验；无法命中 → 进"新知识点建议队列"待人工确认，而非新建野标签。
- 维护静态 KP **前置依赖边**，用于"错在 1.3.2、根因可能在 1.1.4"的溯源。

### 3.7 CollectionBuilder（自动整理错题集）

- **去重**：题干归一化哈希 + 图片感知哈希（同一题多次考到）。
- **聚类**：语义向量聚成"题型族" —— 这是"同类题"中**同类**的定义来源，比 KP 更细。
- **汇总**：`知识点 × 错因` 矩阵 + 掌握度分数。掌握度**必须带样本量置信度**：错 1 题 ≠ 错 8 题。
- 产出诊断报告，每条结论可点击回溯原题证据。

### 3.8 PracticeGenerator（生成同类题）— 风险最高

准确率靠**优先级阶梯 + 校验门禁**，而非"提示词写得更好"。

优先级阶梯：

| 级别 | 手段 | 准确率 | 说明 |
|---|---|---|---|
| **G1** | **检索同考点同型题**（本地错题历史 + 公开题库数据集 + 用户上传教辅） | 最高 | 现成题带权威答案。**"生成"应是最后手段，不是第一手段** |
| **G2** | **参数化变式** | 高 | 基于已验证原题做数值/函数/情境替换；数学类用 sympy **确定性重算答案** |
| **G3** | **LLM 仿写** | 需严格门禁 | 仅 G1/G2 覆盖不到时使用，必须带参照题、评分标准、自解答案 |

校验门禁（任一不过不得下发，且全部可机器复现）：

1. **独立求解一致性** —— 另一求解 pass（不同模型族或不同温度，**看不到生成时附带的参考答案**）重做，答案需一致。
2. **可解性** —— 求解若被迫"补充假设"，判为条件缺失/矛盾 → 拒。
3. **歧义与选项检查** —— 选择题需"唯一最优"；干扰项需有区分度且不错误；多解题需显式声明。
4. **符号验算** —— 数学/理科可形式化部分走 sympy，不信语言判断。
5. **KP 一致性** —— 生成题重新过一遍 KnowledgeTagger，命中目标 KP 才算"同类"。
6. **难度对齐** —— 对齐源题难度带，按梯度要求允许 +0.5 档。

未通过项进隔离区标 `unverified`，**永不静默下发**；练习卷上给可见徽章。
判题：客观题结构化作答自动批改；主观题 rubric + 双评 LLM judge，分差超阈值降级人工。

## 4. 数据流转

一次完整闭环：

```
用户: "同步我的错题，分析这学期数学，给我 10 道针对性练习"

① zx_status()               AuthBridge 探针 → 会话失效 → 请求登录
② zx_login_start()/wait()   用户在浏览器完成登录+验证码；仅 Cookie 被收割
③ zx_sync(scope="2026秋", subject="math")
    Collector:  考试列表 → 每场[逐题得分表 + 原卷快照] → raw_artifact(不可变)
    Normalizer: 得分表 ⋈ 原卷(+VLM OCR) → WrongQuestion[] → Store
    返回: {新增:42, 跳过:8, 解析失败:3, 需人工:3}        ← 只回摘要，不回全文
④ zx_diagnose()
    ErrorAnalyst 逐题错因 ┐
    KnowledgeTagger 逐题标 KP ┘→ Store → CollectionBuilder 去重/聚类/矩阵
    返回: Top5 薄弱 KP、错因分布、每个结论的证据题 id
⑤ zx_practice_generate(kp="K-1.3.2", error="方法选择", n=10)
    G1 检索 → 不足则 G2 变式 → 不足则 G3 仿写 → Verifier 门禁 → practice_item[]
    返回: 题目卡片（默认不含答案）
⑥ zx_practice_submit(attempt[]) → 判题 → mastery_state 更新 → 回到 ③④
⑦ zx_export("错题本.pdf" | "anki.csv" | "jsonl")
```

两条**关键交互约定**：

- **上下文经济性**：工具返回**稳定 ID + 摘要 + 分页游标**，绝不一次把 200 道题全文灌进模型上下文；详情走 `zx_get_question(id)`。
- **答案隔离**：出题与下发答案走不同工具/字段，默认不把答案返回给 Agent。
  否则 AI 会一边出题一边把答案讲给用户，练习失效。

### MCP 工具面（粗粒度、面向 Agent 人体工学）

`zx_status` · `zx_login_start` · `zx_login_wait` · `zx_logout` · `zx_sync` ·
`zx_list_wrong_questions` · `zx_get_question` · `zx_diagnose` ·
`zx_practice_generate` · `zx_practice_submit` · `zx_export`

设计规则：返回稳定 ID 与指针、支持分页、永不泄漏凭据、超长文本截断并提供 `fetch_more`。

## 5. 关键约束与处理

### 5.1 账号授权与隐私

| 约束 | 处理 |
|---|---|
| 凭据泄露 | 密码只由用户在真实浏览器输入，模型与日志全程不可见；Cookie 进 OS keychain；日志出网前脱敏 |
| 未成年人数据（PIPL + 未成年人网络保护条例） | 纯本地存储为缺省且**不做成开关**；姓名/班级以哈希别名入库；导出物默认不含身份标识 |
| 平台 ToS：私有接口自动化访问很可能不被允许 | 明确告知用户；默认走"用户主动导出 / 用户自己的已登录会话"；ApiCollector 默认关闭需显式开启；只读、不限速地慢 |
| 越权 | 端点/URL 白名单；**写操作一律不做**；单次会话请求上限；一键注销 |
| 共享设备 | 会话绑定本机 + 可选口令锁；工作目录不放入云同步盘（若 Desktop 被 OneDrive 纳管需提示） |

> 自用（自己/自己孩子账号）上述基本够用。若做成**面向他人的产品**，需先解决学校/平台授权与监护人同意 —— 技术架构救不了合规问题，属硬门槛，建议先行确认。

### 5.2 错题数据获取与解析

- **最大不确定性 = 学生账号里到底能看到什么**。必须**第一步做探针验证**，登录后打开错题本 + 成绩详情，录 HAR/DOM 快照，确认四件事：
  (a) 错题是否逐题可见；(b) 有无标准答案与解析；(c) 有无步骤分；(d) 题目是文本还是图片。
  **这决定 L1/L2 的可行上限，不做完就写代码是本方案最大风险。**
- 解析失败不得静默丢题：进"需人工"队列，允许用户手改或补图。
- 图片/公式为主的学科（物理、化学、几何）：VLM 抽取必带 `ocr_conf`，低置信度不进入自动错因分析。
- 平台改版监控：以"解析失败率突增"为告警信号。

### 5.3 生成练习题的准确性保障

- **能确定性验证的地方绝不留白**：数学可 sympy 即 sympy；不可形式化的靠双求解一致性。
- 优先级：**检索/变式 > 全新创作**。
- 三道防线：独立求解 → 重新标 KP → 隔离 `unverified`。
- **反馈闭环**：练习做错但事后被判"题有问题" → 回流生成器负样本。这是唯一能长期提升准确率的机制。
- **明令禁止**：让模型自己声明"已验证"。校验状态只能来自代码路径。

## 6. 技术选型对比与推荐

| 维度 | 选项 | 优 | 劣 | 结论 |
|---|---|---|---|---|
| 语言/运行时 | **Node + TypeScript** | 与宿主生态一致（browser MCP、MCP TS SDK）；Playwright 一等公民；单进程 | 符号计算弱 | **✅ 主** |
| | Python | `zhixuewang-python` 可参考；sympy 强 | 工具链割裂；分发麻烦 | **✅ 作 sidecar 专做数学验算** |
| 采集 | Playwright **持久化 profile + 网络响应拦截为主、DOM 选择器为辅** | | | JSON 响应体比 CSS 选择器稳定一个数量级，**抗改版核心手段** |
| 浏览器通道 | 复用宿主已有 browser-use / chrome-devtools MCP | 少一份依赖，可复用用户已登录会话 | | **✅** |
| 存储 | SQLite + FTS5 | 需要多对多与聚合 | | **优于纯 JSONL** |
| 模型分工 | VLM(原卷/题目图/作答图) · 强推理模型(错因+独立求解) · **不同模型族做第二求解器**(独立性才有意义) · embedding(去重/聚类/KP召回) | | | |
| 知识点树 | 内置静态版本化 KP 包（按学段/学科/教材版本） | | | **拒绝动态生成** |

## 7. 预期输入 / 输出

### 输入

- **一次性**：账号绑定（用户在浏览器完成）；学段 + 学科 + 教材版本（决定 KP 树）。
- **常规**（自然语言，Skill 映射到工具）：
  `同步` / `分析这学期数学` / `我二次函数最值不行，出 5 道` / `上次那 10 题做完了，对答案`
- **兜底人工输入**：错题本截图、试卷 PDF、手写作答照片 —— 不是降级方案，是长期存在的主输入之一。

### 输出

1. **同步回执**：新增/跳过/解析失败/需人工 + 错题卡片列表（短）。
2. **诊断报告**（Markdown / HTML / PDF）：`知识点 × 错因` 热力矩阵、Top-N 薄弱点、每条结论可点开原题证据、掌握度 + 样本量置信度。
3. **逐题错因卡**：题干摘要 →「我的作答 vs 标准答案」并排 → 错因标签（置信度 + 引用 span）→ 涉及知识点 → 一句话建议。
4. **练习卷**：Markdown / HTML / PDF / JSONL；每题含 **变式谱系**（源错题）、参考答案+解析、KP 标签、难度、**验证状态徽章**（verified / unverified）；答案区分离，可单独打印。
5. **批改与回写**：结构化自动判分；主观题 rubric 评分 + 分差降级；掌握度更新并刷新诊断。
6. **导出**：Anki CSV / JSONL（可迁移）/ 可打印错题本 PDF。
7. **诚实的失败输出**：分析不了就明说并指出缺什么（缺标准答案 / 图太糊 / 样本不足）。
   这是**正式产物之一**，不是异常堆栈。
