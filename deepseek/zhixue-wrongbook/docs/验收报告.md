### 3.5 第二轮补测：又查出 2 个真实缺陷，都修了

第一轮验收只覆盖了主干。但有一条路它**完全没走到**：
**通道 B 的写入链路 `sync()`** —— 411 行适配器里最核心的函数，
也是你给了 Cookie 之后**第一个会跑**的代码。

我用假对象（`FakeStudent` / `FakeTopic`，字段名照源码 `models.py` 抄）
把它离线跑通，过程中查出两个真 bug：

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 1 | **`download_images` 处理 `file://` 时直接 `url[7:]`** | Windows 上 `file:///D:/a.png` 会变成 `/D:/a.png`（开头多个斜杠），路径不存在；而且图片根本没进 `images` 目录，原文件一移走题库就瞎了 | 用 `urlparse` 正确转路径，并且**把文件复制进 images 目录**（数据自包含） |
| 2 | **`topicSetId` 兜底会跨考试误用** | `topicSetId` 是「某场考试的某学科」的标识。原实现拿**最新考试**的 topicSetId 去给**任意考试**做兜底重试，会得到一个「看似成功实则错乱」的结果——比直接失败更危险 | 只在「正在同步的考试 == 最新考试」时才启用兜底；并把「哪个参数生效了」写进同步报告 |

补测还顺手修了一处**谎报**：`zx_session_clear` 在没存过 Cookie 时也回报「已删除 keyring」，
让人以为凭据被动过。现在只在确实存在时才报删除。

补测覆盖的其余路径（50 项全过）：

- 40217 重试确实被触发、且生效参数被记进报告
- 一个学科失败**不中断**整次同步（E2/数学 记错误后继续）
- 难度刻度未知时报告给出警告 + 每题的原始难度值被记进 notes（供核实刻度用）
- `standard_answer` 是 URL 时正确回退到 `answer_html`
- 图片落盘 + 记到对应题上
- 二次同步只 updated 不 added（指纹去重）
- 学科筛选生效
- `.docx` 解析（答案/解析/作答/得分/难度全中，置信度 1.0）
- `.pdf` 解析（自建最小 PDF 验证 pypdf 通链路；无中文标签时**不凭空产生答案**，置信度 0.40 会被统计排除）
- 扫描版 PDF（无文本层）明确报错，**不伪造结果**
- DPAPI 加密往返 + 落盘内容确实不是明文
- 老库迁移补列且不丢数据

### 3.6 第三轮：接上真实账号后，又查出 2 个真缺陷

前两轮全是离线的（假对象 / 样例文件）。第三轮用真实 Cookie 打通链路，
暴露出两个**离线测试原理上抓不到**的缺陷：

| # | 缺陷 | 后果 | 修法 |
|---|---|---|---|
| 3 | **`make_id` 漏了考试维度** | `id` 是 `questions` 表的**主键**，但生成规则是 `zx_<年>_<学科>_<序号>`，而 `seq` 是「每场考试 × 每学科」内部从 1 重来的。于是同一年两场数学考试的第 1 题都算成 `zx_2026_math_0001` —— 第一场 15 题入库成功，第二场 **12 题全部**报 `UNIQUE constraint failed: questions.id` | 补上考试摘要（`exam_name + exam_date` 的短哈希），形如 `zx_2026_math_3f2a_0001`。函数签名里本来就有 `exam_name` 参数、只是函数体没用 —— 原设计就打算这么做 |
| 4 | **测试套件会删掉用户真实凭据** | `tools/mcp_e2e.py` 只把 `ZX_DB_PATH` 指到临时库，就以为「不碰真实数据」了。但**凭据存储不属于数据库** —— 它调的 `zx_session_clear` 把用户存在 Windows 凭据管理器里的 `zhixue-wrongbook / zx_cookie` **真的删了**，用户被迫重新登录。而 `tools/edge_test.py` 的 D 段也在往真实的 `data/.session.bin` 里写测试值 | 把凭据命名空间做成环境变量可覆盖（`ZX_CRED_SERVICE` / `ZX_CRED_KEY` / `ZX_CRED_FILE`），两个测试各自指向一次性命名空间 |

**缺陷 4 的验证方式**：往真实命名空间写入一个哨兵值 → 跑完三套测试 →
确认哨兵原封不动 → 清理。修复前哨兵必被删除，修复后安然无恙。

**缺陷 3 的验证方式**：新增回归测试 G 段（10 项），用「两场同年同学科的考试、
序号都从 1 开始」精确复现撞车场景；同时覆盖 id 生成稳定性、缺考试名时的行为，
以及「万一还是撞了」的兜底改名路径。

另外顺带修正一处**判断错误**：`scan_login.py` 把智学网接口返回的
`errorCode == 0` 当成功、其余当失败，但实测**成功码是 200**
（`{"errorCode":200,"errorInfo":"操作成功"}`）。原判据会把成功的登录
判成失败。已改为同时接受 0 和 200。

测试规模变化：主干 44 + 边界 50 + MCP 24 = **118 项**（第三轮新增 15 项）。

### 3.7 第四轮：补历史 / 道法知识点词表（2026-09-25）

**根本提交不进分析** —— 词表里没有这两科，`submit_analysis` 的知识点闸门

## 4. 文档未明确或有歧义的地方：指出 + 处理方式

这是你特别要求的部分。逐条列，**每条都说明我是怎么选的、为什么**。

### 4.1 ⚠️ `difficulty` 的刻度未知（影响最大）

- **文档说：** 0~1 浮点，示例 `0.62`；`check_practice` 硬约束是「落在 ±0.15」
- **实际：** 库源码里是 `int`，刻度未知
- **处理：** 不猜。加 `config.yaml` 的 `difficulty.scale`（默认 `unknown`）；
  模型里加 `difficulty_scale` 字段记录每条数据用的是哪种刻度；
  **`unknown` 时难度闸门自动降级为软参考并给出警告**。
  跑 `verify_p0.py` 拿到真实取值范围后填上，闸门自动恢复为硬约束。
- **理由：** 拿一个错的阈值假装闸门有效，比没有闸门更危险——它会给出虚假的通过。

### 4.2 `standard_answer` 是文本还是 URL

- **文档说：** 标准答案
- **实际：** 源码注释写 `# 网址`
- **处理：** 适配器检测「是否像 URL」：像就用 `answer_html` 当正文，
  把 URL 记到 `standard_answer_url` 并在同步报告里标明；不像就正常当文本用。
- **理由：** 两种都兼容，且让人知道实际拿到的是哪种。

### 4.3 `get_errorbook` 第二个参数到底是 paperId 还是 topicSetId

- **矛盾点：** 形参名叫 `topic_set_id`，但请求里发出去的键名是 `paperId`；
  而 `get_subjects()` 的 `Subject.id` 来自 `paperId`，
  `get_latest_exam()` 的 `Subject.id` 却来自 `topicSetId`
- **处理：** 先用 paperId 调；报 40217 就用 topicSetId 重试一次，
  把「哪个生效了」写进同步报告
- **理由：** 这是可验证的降级，不是猜测。

### 4.4 文档说 `zx_sync` 是「唯一联网 + 用会话的工具」——不准确

- **矛盾点：** `zx_list_exams`、`zx_session_status`、`zx_session_set` 都要用会话，
  前者还要联网
- **处理：** 把「唯一」重新表述为：**`zx_sync` 是唯一联网且写库的工具**；
  其余用会话的工具只读
- **理由：** 原表述与工具清单自相矛盾，但意图很清楚（限制写操作），按意图实现。

### 4.5 知识点路径写法：文档示例用两段，规范说三段

- **矛盾点：** 第 7 节示例写 `"一元二次方程/判别式"`（两段）；
  同一节又说是「学科/章节/知识点」层级路径（三段）
- **处理：** 规范形式定为三段；**同时接受两段和纯知识点名，
  但要求在该学科内唯一命中**，命中多个或零个都拒绝并返回候选
- **理由：** 模型偶尔少写一段是常态，直接拒绝会让人反复试错；
  但「有歧义就拒绝」保证了不会有静默的错误标注。

### 4.6 `evidence` 是「描述」还是「引文」

- **矛盾点：** 第 7 节示例是描述（`"学生直接代入求根，未讨论判别式符号"`）；
  第 8.1 节又要求「引用的片段必须能在题干或学生作答中找到」
- **处理：** 分层判定——
  1. 有引号（「」"" 等）→ 引号内的片段必须逐字定位到
  2. 没引号 → 允许最长公共子串 ≥6 字
  3. 引文短于 4 字（如单选题的 `"D"`）→ 通过但**给警告**，
     提示「可能是巧合命中，建议引用选项原文」
- **理由：** 严格要求引文会把单选题逼死；完全放开又挡不住编造。
  分层 + 警告是能同时保住「可用」和「可信」的做法。

### 4.7 掌握度公式里「距今」的基准日没定义

- **文档：** 「距今 ≤30 天 → 1.0」，但没说从哪天算
- **处理：** 取**考试日期**（`exam.date`），缺失时退到 `fetched_at`
- **理由：** 掌握度反映的是「那段时间学得怎么样」，用考试日期更贴近真实轨迹。
  如果同一场考试补抓两次，用 `fetched_at` 会让权重突然变新，属于人为失真。

### 4.8 错因枚举里有「粗心抄错」，但文档又说「不要只说粗心」

- **处理：** 保留 8 类枚举不变；在 `prompts/analyze-v3.md` 里写明
  「『粗心』不是错因——判断是粗心时必须进一步区分是审题失误、计算错误、
  还是粗心抄错」
- **理由：** 枚举是契约不能动，但提示词可以约束模型的表述方式。

### 4.9 纯图片题（无任何文本）证据无法定位怎么办

- **文档：** 「证据定位不到就拒绝」
- **问题：** 题干和作答都是图片时，字符串定位在原理上做不到
- **处理：** 走专门的「无法校验」分支——不误判为造假（不拒绝），
  但也不假装通过：该项降级为软项、给出警告、**强制 `needs_review=true`**
- **理由：** 「拒绝」会让纯图片题永远无法入库；「通过」是自欺。
  转人工复核是唯一诚实的第三条路。

### 4.10 文档说输出 PDF，但 PDF 需要外部渲染器

- **处理：** HTML 一定生成；PDF 探测 weasyprint / wkhtmltopdf / Chrome / Edge，
  都没有就返回 `available: false` + 一句「浏览器打开 HTML 后 Ctrl+P 另存为 PDF」
- **理由：** 不为了「有 PDF」而静默失败或偷偷装东西。

### 4.11 数据模型缺字段

文档第 7 节列了 7 个新增字段，但实际实现还需要两个：

| 补充字段 | 为什么必须有 |
|---|---|
| `difficulty_scale` | 见 4.1。没有它就无法判断「这个难度值能不能直接比」 |
| `first_seen_at`（仅存库，不进模型契约） | `fetched_at` 是「最近一次抓取」，会因重复同步而刷新；「第一次见到这道题」是另一个信息，不能丢 |

### 5.4 新增功能：个性化诊断前必须确认科目（2026-09-24）

**需求**：用户让 AI 根据错题生成「个性化诊断」之前，助手必须强制询问
用户要诊断哪一科（语文 / 数学 / 英语 / 物理 / 历史 / 道法……）。

**为什么不能只写一句提示词**：流程约束写在提示词里是拦不住模型的。
所以把它落到数据面上，做成宿主绕不过去的确定性闸门。

| 机制 | 位置 | 性质 |
|---|---|---|
| 科目必填，缺失即拒绝并返回 `ask_user` 话术 | `zx_diagnosis` / `zx_profile` | 确定性，绕不过 |
| `user_confirmed` 必须为 true，否则拒绝 | `zx_diagnosis` / `zx_profile` | 声明式，可伪造但会留痕 |
| 每次通过的诊断写 `diagnosis_log` | SQLite `diagnosis_log` 表 | 审计，事后可查 |
| 「先问科目」写进硬规则 0 | `skill/zhixue-wrongbook/SKILL.md` | 提示词级，靠宿主老实执行 |

三道检查的顺序是有意的：先「问什么」（缺科目 → 给候选清单），
再「问没问」（未确认 → 给问话），最后「这科有没有数据」（无数据 → 让用户先同步）。
反过来的话，用户会被问一科、答完才被告知「这科没数据」，白问一轮。

**新增/改动文件**：

| 文件 | 改动 |
|---|---|
| `core/subjects.py` | 新增。科目清单 = 标准学科顺序 ∪ 受控词表 ∪ 本地库 |
| `core/constants.py` | 加 `SUBJECT_ORDER`（固定学科顺序）与 `SUBJECT_ALIASES` |
| `core/store.py` | 加 `subject_stats()` / `diagnosis_log` 表 / `log_diagnosis()` / `diagnosis_logs()` |
| `server.py` | 加 `_subject_gate()`、`zx_subjects`、`zx_diagnosis`、`zx_diagnosis_log`；`zx_profile` 改必填 + 加闸门 |
| `skill/zhixue-wrongbook/SKILL.md` | 加「硬规则 0」+ 场景 5，工具表补 3 项 |
| `tools/acceptance.py` | 加 J 段（科目清单与审计，7 项） |
| `tools/mcp_e2e.py` | 加科目闸门三态断言（8 项） |
| `tools/live_smoke.py` | 改走新流程；**刻意不用 `zx_diagnosis`**（无人值守脚本没有真实用户确认，会在真实库里留下假审计） |

**诚实说明：这道闸门拦得住什么、拦不住什么**

- **拦得住**：「不给科目就拿不到数据」是确定性事实；「该问什么」有现成话术。
- **拦不住**：用户**真的**有没有被问过。没有任何代码能验证这件事 ——
  `user_confirmed=true` 终究是宿主的一句声明。这里没有假装能验证，
  而是退一步**让这句声明必须留下痕迹**。没问就传 `true`，
  `diagnosis_log` 里会出现一条记录，用 `zx_diagnosis_log` 一眼能看出来。
- **顺带一个已知缺口（没做，不假装做了）**：受控词表现在有
  数学 / 物理 / 化学 / 英语 / 语文 / **历史 / 道法** 七科（历史道法是
  2026-09-25 补的，见 3.7）。**生物、地理** 还没有 —— 这两科现在
  **能同步、能选中、能被诊断问到**，但要到能做知识点级分析，
  得先往 `data/taxonomy.yaml` 补对应章节。清单里这类科目会如实标
  `in_taxonomy: false`。

### 6.2 校准脚本给出的三个重要发现

跑 `calibrate.py` 的结果（20 对合成标注）：

| 指标 | 正例中位 | 负例中位 | 分离度 | 文档阈值 | 搜出的最优阈值 |
|---|---|---|---|---|---|
| 知识点 Jaccard | 1.00 | 0.00 | **1.00** | 0.6 | 0.05（F1=0.87） |
| 难度差 | 0.04 | 0.03 | **-0.01** | 0.15 | 0.08（F1=0.71） |
| 题型一致 | 1 | 1 | 0 | 必须一致 | — |
| 文本相似度 | 0.177 | 0.029 | 0.148 | （仅参考） | 0.05（F1=0.76） |

**发现 1：文本相似度的分离度只有 0.148，正负例分布几乎重叠。**
这**印证了**文档 8.4 节的判断——数学题换个数字文本相似度就暴跌，
它和「同知识点同难度」相关性很弱，不能当闸门。文档这条改对了。

**发现 2（文档没预料到的）：难度差的分离度是 -0.01，几乎为零。**
负例被判为「不同类」的原因绝大多数是**知识点不同**，而不是难度差。
也就是说在真实场景里，「难度 ±0.15」这条闸门**几乎不会独立否决任何题**。
这不代表它没用（能拦住「同知识点但明显偏难」的题），
但说明闸门的有效性排序是：**知识点 > 题型 > 章节 > 难度**。

**发现 3：搜出的 Jaccard 最优阈值（0.05）远低于文档的 0.6。**
原因是我构造的负例「太干净」（知识点完全不重合）。
真实数据里会有大量「部分重合」的边界样本，阈值会明显上移。
**这正是合成标注不能当结论用的证明**——也说明文档坚持要真实标注是对的。

| # | 局限/风险 | 严重度 | 缓解 |
