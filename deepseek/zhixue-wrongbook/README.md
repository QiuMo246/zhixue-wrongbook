# 智学网错题助手

把智学网里的错题自动拉出来 → 分析每道题错在哪 → 标注知识点 → 找出你最弱的地方 → 出同类题给你练 → 做完自动批改。

按 `../智学网错题助手-架构设计.md`（v2）实现。

---

## ⚠️ 隐私声明（请先读这一段）

> **错题的题干、标准答案、解析、学生作答会被发送到你所使用的 AI 模型进行处理。
> 如果你不希望这些内容离开本机，请使用本地模型。**

具体分工：

| 组件 | 是否联网 | 说明 |
|---|---|---|
| **MCP Server（本项目）** | **零云端调用** | 只做本地 HTTP 请求（智学网）、SQLite 读写、确定性计算。**不调用任何模型 API**（`tools/mcp_e2e.py` 里有静态检查会验证这一点） |
| **宿主模型（你用的 AI）** | 由你自己选 | 你已经在用 AI 助手了，这不是本工具引入的新风险 |
| **智学网** | 唯一的外部服务 | 取数时必须访问，这是需求本身决定的 |

其它隐私约束：

1. **不存账号密码** —— 代码里根本没有密码这个参数
2. **Cookie 存系统凭据管理器**（Windows 凭据管理器 / macOS Keychain），
   不落明文文件；keyring 不可用时降级为 Windows DPAPI 用户级加密文件
3. **数据全在本机** —— SQLite + 图片目录都在项目里
4. **最小必要** —— 只取错题相关内容，**不调用任何同学信息接口**
5. `zx_purge` 是真删（库文件 + WAL/SHM + 图片）
6. 不公开分发，个人自用

```
A 官方导出解析 ── adapters/parsers/zhixue_export.py   ← 完全合规，一等公民
B 现成库 API ──── adapters/zhixuewang.py              ← 主路径
```

- **有官方导出权限就用 A**（不碰账号，最稳）

## 核心设计：能力边界

```
┌──────────────────────────────────────────┐
│  宿主模型 · 推理面（你）                   │
│  读懂题意 / 判定错因 / 标注知识点 / 出题自解 │
└──────────────────────────────────────────┘
      ↓ ① get_questions      ↑ ② submit_analysis
┌──────────────────────────────────────────┐
│  MCP Server · 数据面（本项目）             │
│  拉取错题 / 存取 / 确定性校验 / 导出        │
└──────────────────────────────────────────┘
```

**划线的判据：这个动作需要「理解」吗？**

- 需要理解 → 宿主做（这道题在考什么、学生为什么错）
- 不需要理解 → MCP 做（存 JSON、按知识点筛选、比对答案、统计计数）

**为什么这样分：** 如果 MCP 内部偷偷调模型，就不可审计、不可复现、
token 成本不可控。分开之后，宿主提交的每条结论都要过 MCP 的三道确定性闸门：

1. 错因必须在 8 类枚举内
2. 知识点必须能在 `taxonomy.yaml` 里解析到（只能选，不能造）
3. 证据必须能在题干/标准答案/解析/学生作答里定位到

过不了就拒绝，并说明原因和候选值。**这就是「可审计的推理」落地的地方。**

### 重新同步不会清空你已有的分析结果（2026-09-25 修）

这是本项目修过的最严重的一个缺陷，值得单独写在这里：

`zx_sync` 原来走**无条件全字段覆盖**，而重新抓回来的题**天然没有分析结果**
（分析是你后来让 AI 提交的）。于是**每同步一次，就把已有分析清空一次** ——
实测 27 道题的 `analysis` 从 27 条掉到 0 条，而工具还返回 `ok=true`。

现在改成「**派生字段只在传入值非空时才覆盖**」：

| 字段类别 | 例子 | 能不能被同步覆盖 |
|---|---|---|
| 来源数据 | 题干、标准答案、得分、难度 | ✅ 每次重新抓，可以覆盖 |
| **派生数据** | 分析结果、练习记录、复习历史 | ❌ **不能** |

同步报告里会带 `preserved_analysis` 计数，说明本次**保留了多少条**既有分析结果 ——
让「没被清掉」变成可观察的事实，而不是一个只能翻数据库才能确认的隐性承诺。

### 传了不存在的参数名会被拒绝，不再静默忽略（2026-09-25 修）

pydantic 默认丢弃未知参数，于是 `zx_export_paper(items=..., fmt="pdf")` 会
**返回 `ok=true` 但没有 PDF** —— 最危险的一类失败：不报错，结果是错的。

现在会返回 `ok=false` 并点名是哪个参数，同时给出 `accepted` 参数清单。
（`fmt="pdf"` 作为兼容别名仍然认，正统写法是 `want_pdf=true`。）

## 个性化诊断前必须先确认「科目 + 试卷范围」（2026-09-24 新增，09-25 扩展）

你说「帮我生成个性化诊断」的时候，助手**必须先问你两件事**：

1. **要诊断哪一科？**
2. **要分析哪些试卷里的错题？**

不许默认「全部」，不许挑库里题最多的那科，不许从上一轮上下文里猜。
第二问是 2026-09-25 补上的 —— 只问科目是不够的：

> 一科的错题可能横跨几个月、几十份卷子（周测 / 午练 / 晚练 / 早读）。
> 只说「物理」，「分析哪些卷子」**仍然是助手替你定的** ——
> 范围没被用户确认，等于没确认。

### 试卷范围怎么选：两个维度，是「且」的关系

| 维度 | 取值 |
|---|---|
| **按试卷类型** | 周测 / 午练 / 晚练 / 早读 / 其他 / 全部（可多选） |
| **按时间** | 本周 / 上周 / 近两周 / 本月 / 近一月 / 全部 |

也可以给自定义区间（`since` / `until`，`YYYY-MM-DD`）。
`午练 + 本周` = 只看本周的午练。

### 它实际怎么拦住

| 机制 | 说明 |
|---|---|
| `zx_diagnosis` / `zx_profile` **七道检查，缺一即拒** | 拒绝时返回一句现成的 `ask_user`，助手照读就能问你 |
| `user_confirmed` / `scope_confirmed` 必须为 `true` | 含义是「**我已经问过用户，并得到了明确答复**」，不是「我拿到了许可」 |
| 拒绝理由可区分 | 缺科目 / 科目未确认 / 缺范围 / 范围非法 / 范围未确认 / 该科无数据 / 该范围无数据 —— 助手知道下一步该问什么 |
| **返回的画像真的按范围过滤** | 不是只写一句提示。选「本周午练」就只统计本周午练 |
| 每次通过的诊断写进 `diagnosis_log` | 含科目、试卷类型、时间范围、两处确认声明；用 `zx_diagnosis_log` 核对 |
| Skill 硬规则 0 | `skill/zhixue-wrongbook/SKILL.md` 里写死了这个顺序 |

正常流程长这样：

```
zx_subjects()                       → 拿到候选科目 + 每科题数 + 一句 ask_user
      ↓（把这句话问给用户）
用户回答「物理」
      ↓
zx_diagnosis(subject="物理", user_confirmed=true)
      ↓ 被拒：needs_scope，返回一句带「可选范围 + 各自题数」的 ask_user
      ↓（把这句话问给用户）
用户回答「午练和晚练，本周的」
      ↓
zx_diagnosis(subject="物理", user_confirmed=true,
             paper_types=["午练","晚练"], time_scope="本周",
             scope_confirmed=true)                  → 诊断数据包（只含这个范围）
```

### 说句实话：这道闸门拦得住什么、拦不住什么

**拦得住**：「不给科目 + 不给范围就拿不到数据」是确定性事实，助手绕不过去；
「该问什么」有现成话术，助手不用自己编；
返回的画像**真的只覆盖用户选的范围**（这一条最关键 —— 否则闸门只是句问话）。

**拦不住**：用户**真的**有没有被问过。没有任何代码能验证这件事 ——
`user_confirmed` / `scope_confirmed` 终究是助手的两句声明。所以这里没有假装能验证，
而是退一步**让这两句声明必须留下痕迹**：没问就传 `true`，
`diagnosis_log` 里就会出现一条记录，你用 `zx_diagnosis_log` 一眼就能看出来。

> 顺带一个刻意的设计：**科目清单按固定学科顺序排（语文/数学/英语/物理…），
> 不按题数排。** 按题数排等于数据在替你做决定 —— 题最多的那科永远排第一，
> 你会被带着走。

### 科目清单从哪来

```
标准学科顺序（constants.SUBJECT_ORDER）
   ∪  受控词表（data/taxonomy.yaml 里的学科）
   ∪  本地库（实际有错题的学科）
```

三者要分开看：库里可能有「生物」的错题，但受控词表里还没有生物的知识点 ——
这一科**能列出来、能被你选中**，却暂时做不了知识点级分析。
这种情况会如实标成 `in_taxonomy: false`，不假装可以。

> **受控词表现状（2026-09-25）**：7 学科 / 341 个知识点 ——
> 数学 63、物理 32、化学 22、英语 18、语文 15、**历史 114**、**道法 77**。
> 生物、地理这些科目现在能同步、能选中，但要做知识点级分析，
> 得先往 `data/taxonomy.yaml` 里补对应章节。**这条没做，不假装做了。**

## 知识点受控词表（怎么查、怎么改）

词表是「只能选、不能造」的硬闸门 —— 提交的每个知识点都必须在
`data/taxonomy.yaml` 里找得到。所以标知识点之前，先查一眼：

```
zx_knowledge_points()                                  → 各学科章节数/知识点数总览
zx_knowledge_points(subject="历史")                     → 历史全部 16 章 114 个知识点
zx_knowledge_points(subject="道法", chapter="宪法与依法治国")  → 只看这一章
zx_knowledge_points(query="西安事变", subject="历史")     → 按关键词找准确写法
```

**被拒绝时不要猜。** `submit_analysis` 说「不在受控词表内」时，
用 `query` 查正确写法；**查不到就说明词表里确实没有** ——
这时如实标 `needs_review=true`，不要编一个「看起来像」的名字，
也不要为了过闸门硬套一个不相干的知识点。

### 章节为什么按「内容主题」分，而不是按教材单元名

因为**统编版初中教材正在换新版，单元/课题名变动很大**。实测两版对比：

| | 旧版 | 新版（2025 秋） |
|---|---|---|
| 道法八上 第二单元 | 遵守社会规则 | **维护社会秩序** |
| 道法八上 第七/八课 | （在八下）崇尚法治精神 | **移到八上**：追求自由平等 / 维护公平正义 |
| 历史八上 第 8 课 | 革命先行者孙中山 | **中国同盟会** |

如果把单元名写进词表，学校一换教材版本，路径就全对不上，
分析会成片地被拒绝。所以章节用**断代 / 内容板块**（跨版本稳定），
知识点用**具体考点**。

**代价说清楚：** 章节粒度比教材单元粗一点，`check_practice` 的
「超纲检查」在历史 / 道法上会宽松一些。这是知情的取舍，不是没想到。

**想加知识点**：直接改 `data/taxonomy.yaml` 就行，不用改代码。
加完 `version` 顺手 +1（那个字段只是留痕，不影响已有分析结果）。

## 已知局限（诚实清单）

1. **难度刻度已核实（2026-09-25 复核）。** 库的 `difficulty` 是 `int`，
   `config.yaml` 已填 `scale: raw` / `assumed_max: 3`，
   依据是 314 个样本只出现 `{0,1,2,3}`、且按班级得分率交叉验证过（难度 3 最难）。
   **难度闸门因此处于硬约束状态，不是降级状态。**
   若日后真实数据里出现 4 或 5，说明平台改了刻度，要重新校准这一项
   —— `verify_p0.py` 现在会先读配置再给建议，一致时会明确说「无需修改」。
2. **平台自带考点数据 —— 已确认（2026-09-25）。** `getExamPointsAndScoringAbility`
   返回结构化列表：考点名 + 权重 + 掌握度（0~100）。
   所以「平台没有知识点标注」这个前提**只对了一半**：
   平台给的是**考试级聚合**，不告诉你「第 18 题对应哪个考点」——
   **逐题归因仍是本项目的价值所在。**
   （另注：该接口的成功码是 `errorCode=0`，而 `getCurrentUser` 是 `200`，
   判成功要看 `result` 有没有内容，不能只看错误码。）
3. **客观题的学生选项不在库字段里 —— 但能读出来，而且已打通（2026-09-25）。**
   `get_answer_records` 只返回**逐题得分**（不返回学生选了什么），
   但正好可以用它把错题本条目**对应到具体题号**；
   再用 `get_original()` 拿原始答题卡扫描图（含客观题填涂卡），
   裁剪放大后读出实际选项。
   实测：物理 1372 第 9 题 = B、第 10 题 = A；d7db 第 8 题 = C、第 10 题 = D。
   **所以客观题的错因分析不必停在「只能看对错」**，代价是多一步读图。
   做法见 `skill/zhixue-wrongbook/SKILL.md`。
4. **手写图片识别有误差。** 主观题错因只给倾向性判断 + 置信度，
   看不清的强制 `needs_review=true`。
5. **PDF 导出需要外部渲染器，但通常不用装。** 探测顺序是
   weasyprint → wkhtmltopdf → 本机 Chrome / Edge / Chromium 无头打印。
   最后一档在 Windows 上**不查 PATH 是找不到的**（Chrome/Edge 不注册到
   PATH），所以 `core/export.py` 里额外查了标准安装路径与注册表外的
   字面量路径 —— 2026-09-24 修掉了「明明装了却报未检测到」的假阴性。
   三条路都不通时只出 HTML，并给出 `how_to`。
6. **阈值是先验值，不是校准值。** `tools/calibrate.py` 用的是合成标注（20 对），
   只能演示方法。真正校准需要你标 30~50 对真实题目。
7. **官方导出解析基于通用启发式。** 不保证匹配所有学校的排版，
   每题都带 `parse_confidence`，低置信度的会被统计排除并进复核队列。
